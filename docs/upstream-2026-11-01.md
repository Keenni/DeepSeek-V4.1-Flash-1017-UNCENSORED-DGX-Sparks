# Upstream 2026-11-01: six new engine patches, and why our eight are still needed

**One line:** the MiaAI-Lab four-node recipe moved from `476bbc7` (36 patches) to `e1f6b85` (42 patches) in
29 commits, with the **engine pin unchanged** (`bertholomus/TensorFold@5940208`) and the chat template
byte-identical — so this was a pure patch + script round. Three of the six new patches are real fixes, one is
a load-time speedup we ship, one is a diagnostic, one is test-only. **None of them touches the long-run host
memory problem our 9003-9005 patches address**, which is the interesting part.

## The six patches

| Patch | What it does | Ship? |
|---|---|---|
| `0046` load-prefetch (shalk3) | eight threads `pread` the rank's weight file in 32 MiB chunks up to 4 GiB ahead of the loader's furthest read, so the loader's own reads hit page cache. `TF_DS_LOAD_PREFETCH=0` disables. Author's measurement on one worker, 81.2 GB file, cache evicted before each run: **83.4 s → 27.2 / 27.3 / 27.4 s**; every tensor's sha256 equals the old loader's | **yes** — our weights are on local NVMe, load time is the slowest leg of a start |
| `0042` JSON answer channel | a reply requested as JSON (`response_format` `json_object`/`json_schema`, `guided_json`) stays JSON even when the request also offers `tools`; it used to be parsed as tool calls (`content: null`) | **yes** — a regression against `0036`'s structured output, user-visible |
| `0039` grammar setup result | when a reply grammar failed to build at admission, `LaneHost.setup` freed the job but returned `drop`'s `true`; both callers continued with a freed job (use-after-free) | **yes** — crash class |
| `0040` graph-cache ownership | a decode/drafter graph whose first launch failed was destroyed by `errdefer` but left in the cache map → later hits used a destroyed handle, teardown destroyed it twice | **yes** — crash class |
| `0043` orphan DSML closers | a reply made only of DSML closing tags gets `tensorfold.tool_parse_warning: "orphan_dsml_closers"` + a log line. Diagnostic only; does not fix upstream #14 | included (cheap) |
| `0041` grammar tests | `zig test` compiles again (a `HfText.load` signature the tests still used). Test code only | included (no effect on the binary's behaviour) |

Measured effect of `0046` on our four-node ring: worker `loaded_s` **≈83 s → 28.4 s**; decode and prefill
unchanged (upstream says the same, and we reproduce it). The 4 GiB lead is deliberately bounded because the
page cache and the landing weights compete for the same unified memory.

## What upstream still does not fix

The long-run host-memory climb on the head node is **not** in the MiaAI-Lab series. The three upstream fixes
for it live in `ashhart/TensorFold` main (#1229 tokenizer scratch on a 4 KiB stack, #1230 connection arena
capped at 1 MiB, #1231 template scratch on the template's own arena) and never reached this recipe. Across
all 42 patches, only three touch `server/server.zig`, `core/template/template.zig` or
`core/tokenizer/tokenizer.zig` — `0028` (SSE keepalive), `0033` (metrics), `0036` (structured output) — and
none of them is that fix.

Our own patch series therefore stays:

| Patch | Effect |
|---|---|
| `9001` server/prompt | `prepare()` no longer renders the whole history a second time just to compute `history_len` (head anon peak 22.7 → 13.1 GiB on a 500k-token agent session) |
| `9002` template/eval | `str + str` resizes the arena's last block in place instead of `std.mem.concat` (O(N²) → O(N)); close to dead code once the template renders linearly |
| `9003` server/server | keep-alive connection arena capped at 1 MiB — the connection no longer holds the largest request it ever saw |
| `9004` template | render scratch allocates from the template's own arena, not the request arena |
| `9005` tokenizer | encode/decode scratch on a 4 KiB stack + `BufferFirstAllocator` |
| `9006` host row tables | 4096 → 8192 rows (inert for us: `chunk_rows = 2048`) |
| `9007` two decode switches | `TF_DS_SOLO_OVERHEAD` (fixed head-window overhead instead of a live estimate; **measured −9.3 % single-stream decode with our `DRAFT_MS`**, so it stays off) and `TF_DS_NO_COPIES` (suffix-lookup copy proposals off; on) |
| `9008` engram AIO | a refused Engram row id no longer leaks the AIO batch's buffers |

Expected gain: memory and correctness, **not throughput**. A build with and without 9003-9008 measured the
same prefill and decode within noise — that is the honest result, and it is why the memory patches sat in a
spare binary for a while before being made the default.

## Reproducing

```bash
# authority tree at serving (image source) or at arena (this build)
git am dev/tp4-tensorfold-mia/engine-patches/0005-*.patch   # 9001
git am dev/tp4-tensorfold-mia/engine-patches/0006-*.patch   # 9002
git am dev/tp4-tensorfold-mia/engine-patches/0007-*.patch   # 9003-9008
# upstream 0039-0046 apply first, by filename, in the recipe's zig/patches/
```

`0007` carries one hand-applied hunk in `zig/src/families/dsv41/native.zig` (two `getenv` lines): the tree
it was originally exported from lacked the `errdefer st.lanes.deinit()` context that `0034` adds, so the
patch expects the complete tree. Applying it to the incomplete one still succeeds file by file but leaves the
two switches unwired — check with `strings tensorfold-native | grep TF_DS_SOLO_OVERHEAD`.
